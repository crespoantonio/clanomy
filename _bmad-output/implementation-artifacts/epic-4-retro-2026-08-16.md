## 2. Retrospective Discussion Summary

### What Went Well
* **Secure File Cleanup Pipeline:** Successfully implemented temporary file generation (`tempfile.mkstemp`) wrapped in a guaranteed `try-finally` context that physically deletes the files immediately after dispatch, preventing storage leak of decrypted financial PII.
* **SQLModel Cascade Purges:** Effectively configured ORM cascading deletes (`cascade="all, delete-orphan"`) and database constraints (`ondelete="CASCADE"`) to automatically wipe all User and Transaction records upon Family/User deletion.
* **Keyword Heuristic Bypass:** Resolved the double-Ollama latency regression on simple expense logs by running a fast Python-based keyword check. Obvious logs now bypass intent parsing and confirm in under 3 seconds.
* **Previous Retro Follow-through:** Fully delivered on all 4 commitments from Epic 3 (TelegramWebhook direct routing, Aggregation optimization, Cascade tests, and Export research).

### Challenges and Lessons Learned
* **Pydantic Validation Failures on Omitted Fields:** `ParsedQueryIntent` required `timeframe` to be passed, which broke non-timeframe intents (like `delete_account`). Resolved by making `timeframe` default to `"this_month"`.
* **Missing Default Engine Fallbacks:** Singletons instantiated without arguments (such as `AccountService()`) in production failed due to uninitialized engines. Resolved by setting `engine = engine or db_engine` inside class initialization.
* **SQLAlchemy Deletion State:** When testing database cascade deletes, attempting to assert fields on a deleted object results in an `ObjectDeletedError`. Solved by extracting references (like `tx_id`) before calling deletion.
