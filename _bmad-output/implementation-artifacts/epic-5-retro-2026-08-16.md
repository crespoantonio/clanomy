## 2. Retrospective Discussion Summary

### What Went Well
* **Secure Invite Token Ingress:** Successfully built `FamilyInvite` table with cryptographically secure tokens (`secrets.token_urlsafe(16)`), 48h UTC expiration, and Telegram `/start join_<token>` deep-linking.
* **Collective & Member-Specific Scoping:** Upgraded `QueryService` to handle both collective family spending ("our spending this month") and member-filtered queries ("What did Maria spend?").
* **Batch User Resolution:** Prevented N+1 database queries by batch fetching family user records into an in-memory map before decrypting transactions.
* **Export Attribution Integrity:** Standardized CSV (`"Logged By"`) and JSON (`"logged_by"`, `"user_id"`) exports to include contributor attribution.
* **Previous Retro Follow-through:** Fully delivered on all 3 action items from Epic 4.

### Challenges and Lessons Learned
* **Member Aggregation Keying Collisions:** Grouping member totals by display name alone caused spending merges if two members shared the same display name or lacked usernames. Resolved by grouping by `user_id` before formatting unique display keys.
* **Telegram Bot Username Resolution:** Generating invite links requires the bot's username (`https://t.me/<bot_username>?start=join_<token>`). Added dynamic bot username resolution via Telegram API `getMe` with fallback to `TELEGRAM_BOT_USERNAME` in config.
* **Orphan Family Cleanup:** When a user joins a new family via an invite link, their previous single-member family with 0 transactions is automatically purged to keep the database clean.
